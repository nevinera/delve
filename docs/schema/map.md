# Map

A Map is one visual floor or area within a Zone. A zone contains at least one map.

See [common.md](common.md) for `Location`, `Position`, `floatRange`, and `RespawnConfig`.

## Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | yes | Slug used to reference this map within the zone (e.g. `"ground_floor"`). |
| `name` | string | yes | Display name (e.g. `"Ground Floor"`). |
| `elvl` | integer | no | Elevation of this map, if different from the enclosing zone's. See [stats.md](../stats.md). Defaults to the zone's `elvl` when omitted. |
| `imageUrl` | string | one of these | URL of the map background image. A map needs an `imageUrl`, a `cellMap`, or both; with both, only the image is used. |
| `cellMap` | CellMap | one of these | A hand-drawn grid of terrain cells the client renders as the map's ground (see **CellMap** below). Ignored while there's an `imageUrl`, but still validated, so removing the image brings the cells back. |
| `thumbnailUrl` | string | no | URL of a small preview image (relative to this map's own file, same convention as `imageUrl`). Generated by the map editor alongside `imageUrl` when a background is saved; absent on maps saved before this field existed, or if generation failed. Editor tooling only (e.g. the zone editor's map list/graph) - the game server and client do not read this field. |
| `pixelDimensions` | object | with `imageUrl` | Image dimensions in pixels: `{ "width": int, "height": int }`. Ignored without an image. |
| `feetDimensions` | object | yes | Map dimensions in feet: `{ "width": float, "height": float }`. Used to convert pixel coordinates to world coordinates. With a `cellMap` and no image, it must match the cells' rendered size (within 0.01 feet). |
| `lighting` | string | no | `"daylight"` or `"torchlight"`: how the map is lit, in the game and the map editor's walk preview. Daylight is ambient light and sun under a distance haze; torchlight is a light the player carries, fading to black. Either way the player sees 60 ft clearly, fading out by 120 ft. Defaults to `"daylight"` when omitted. Client-only - the game server does not read this field. |
| `barriers` | array of Barrier | no | Impassable obstacles on this map. |
| `fillPoints` | array of Location | no | At most 100. Each one fills the region of the map it sits in, making it impassable like the area outside the map's walls (see **Fill** below) - for voids inside the playable area, like a closed-off rock. |
| `connections` | array of MapConnection | no | Entry/exit points on this map. The zone defines how connections pair up and which are entry points. |
| `units` | array of Unit | no | Units initially present on this map. See [unit.md](unit.md). UnitType keys must be defined in the enclosing zone's `unitTypes`. |
| `ncus` | array of NCU | no | Non-combat units initially present on this map. See [ncu.md](ncu.md). |
| `interactables` | array of Interactable | no | Things players use for quests: snares, totems, cages. See **Interactable**. |
| `places` | array of Place | no | Named, tagged areas of the map, for building a zone in layers (see **Place** below). The game ignores them. |
| `respawn` | RespawnConfig | no | Overrides the zone's `respawn` for every unit on this map, unless a unit overrides it again. See [common.md](common.md#respawnconfig). |
| `leashRadius` | number | no | Feet. How far an engaged NPC on this map may get from where it was pulled before it gives up (see **Leashing** below). Default 120 (about WoW's 40 yards). A unit may override it. |
| `hardLeash` | boolean | no | `true` makes NPCs on this map leash the moment they pass `leashRadius`, fight or no fight - for boss arenas and tight dungeon rooms. Default `false`. A unit may override it. |
| `annotations` | Annotations | no | Notes for an LLM (and the author): intent, plans, backstory, personality. Never read at runtime, and never copied into game state. See [common.md](common.md#annotations). |

### Leashing

An NPC records where it was standing when it was first pulled (its leash point; not its spawn
point, since a patrol can range farther than its leash). While engaged, its distance from that
point decides when it gives up, following modern WoW:

- Within `leashRadius`, it gives up after 10 seconds with no damage dealt by or to it (a target
  it can't reach).
- Beyond `leashRadius`, it keeps chasing while the fight continues, and gives up once 6 seconds
  pass with no damage either way.
- Beyond 3 x `leashRadius`, it gives up immediately.
- With `hardLeash`, it gives up the moment it passes `leashRadius`.

Distance carries across one map crossing (from the leash point to the connection it left
through, plus its distance from the connection it arrived at); following onto a third map gives
up immediately. Giving up is a reset: the NPC, and its whole group, drop the fight, heal fully,
lose their debuffs, and walk home immune to everything until they arrive.
### Fill

The walls, line connections and the map's edge divide a map into regions. Every region that
reaches the map's edge (somewhere a wall doesn't run along it) is filled, as is every region
holding a `fillPoints` entry; circles are always filled. The client draws the fill as raised
ground. Before regions are traced, near misses are closed: wall and line-connection ends within
0.5 feet of each other or of any wall or line get joined to it, and an end within 0.5 feet of a
circle's edge joins its center.

Nobody can stand in the fill. The validator requires every line connection to have open ground on
exactly one side, and every point connection to sit on it. The game server moves a unit whose
center ends up in the fill out to the nearest open ground, routes NPCs around it, and sets units
arriving through a line connection down on its open side, facing into it. A map that fails the
validator's fill rules (one published before them) has no fill on the game server.

## CellMap

A grid of terrain cells, one character each, plus trails drawn across them. The client renders it
into the map's ground (client/src/cellMap/), the same every time for the same data. Client-only:
the game server doesn't read it, and cells don't block movement; walls are still barriers. The map
editor's Auto Barriers makes them from the cells: walls around trees (rock) block sight, and
walls around water don't.

| Field | Type | Required | Notes |
|---|---|---|---|
| `version` | integer | yes | `1`. |
| `theme` | string | yes | The look, and the grid types that go with it: `"glade"` (a summer wood), `"autumn"` (turning leaves), `"winter"` (snow, pines, iced water) or `"cave"` (rock, inked and hatched like a hand-drawn cave map). Themes live in client/src/cellMap/themes.json, their looks in client/src/cellMap/style.js. Every theme has the same cell alphabet, so a map can change theme. |
| `colors` | object | no | Overrides some of the theme's colors, as `"#rrggbb"`: `{ "meadow": "#b8c98a" }`. Keys must be the theme's colors (its `colors` in themes.json; glade: `meadow`, `tallGrass`, `marsh`, `water`, `forest`, `crown`, `tuft`, `tallTuft`, `pool`, `reed`, `trail`, `road`, `bridge`, `ink`). |
| `grid` | object | yes | `{ "type": "hex", "cols": int, "rows": int }`. `type` must be one the theme supports (glade: `"hex"`). `cols` and `rows` are 1 to 200. |
| `seed` | integer | yes | Varies the decorations (tree crowns, grass tufts and so on) without changing the terrain. |
| `cells` | array of string | yes | One string per row, one character per cell, `rows` strings of `cols` characters: `.` meadow, `%` tall grass, `~` marsh, `w` water, `T` trees. A cave calls them floor, gravel, puddles, water and rock. A new map starts all `T`. |
| `trails` | array of Trail | no | Paths across the cells, drawn over the ground and under the decorations. Nothing grows on them, and they cut through trees. |
| `bridges` | array of Bridge | no | Wooden bridges, drawn over the water. |
| `exits` | array of Exit | no | Gaps in the map's edge where connections lead off it, at most one per side. |
| `places` | array of CellPlace | no | Areas of the map, which Auto Barriers turns into its places (see **Place**). The generator writes one per area. |

A hex grid has flat-topped hexes, always 5 feet across the flats (so trees and grass are the same
size on every map), with odd columns half a cell lower. Its size in feet is
`width = r * (1.5 * cols + 0.5)` and `height = 5 * rows + 2.5` (no half cell when there's one
column), where `r = 5 / sqrt(3)`. Cells are
y-down from the top-left, like the image: row 0 is the map's top edge.

A **Trail** is `{ "type": string, "width": float, "points": [[col, row], ...] }`: a curve through
at least two points, in cell coordinates (whole numbers are cell centers; fractions fall between
them), and `width` in cells. A free end fades out; an end on another trail joins it. `type` is
optional, `"trail"` by default: `"trail"`, `"deerPath"` (narrow, faint), `"road"` (wide, rutted) or
`"worn"` (a worn floor, for caves); each has its own look and default width (see
client/src/cellMap/style.js's PATHS). A theme's `paths` in themes.json lists its types, the
first for new trails.

A **Bridge** is `{ "from": [col, row], "to": [col, row] }`: a deck from one cell to another, in a
straight line through neighboring cells (one of the six ways a hex's edges face), 1 to 8 cells
from its start. Start and end it on land. Auto Barriers cuts the water's walls where the deck is
and rails it down both sides (railing an end too, if it's over water); the deck is 6 feet wide.

An **Exit** is `{ "side": "north" | "east" | "south" | "west", "from": int, "to": int }`: the
cells along one side of the grid from index `from` to `to` (columns along the north and south
sides, rows along the east and west), open ground leading off the map. Auto Barriers makes each a
line connection named for its side (`"north"`, ...), along the map's edge between the walls either
side of the gap, so the map's fill stops there; one already named that is replaced.

A **CellPlace** is `{ "identifier": string, "polygon": [[col, row], ...] }`: an outline in cell
coordinates (like a trail's points), at least 3 points. Auto Barriers makes each a Place with the
same identifier, bent as the walls are; a Place already named that keeps its name, description,
tags and annotations and takes the new outline. The generator's places (`area_1`, `area_2`, ...)
put every cell in one, each area's doors and corridors split between the areas they join.

```json
"cellMap": {
  "version": 1,
  "theme": "glade",
  "colors": { "forest": "#2f4a2c" },
  "grid": { "type": "hex", "cols": 4, "rows": 3 },
  "seed": 11,
  "cells": ["TTT.", "T...", "..%~"],
  "trails": [{ "width": 0.8, "points": [[0, 2], [3, 0.5]]}]
}
```

## Barrier

Barriers block unit movement and, unless `blocksSight` is `false`, line-of-sight. Both kinds
take an optional `blocksSight` (boolean, default `true`): `false` is for things you can see and
shoot across but not walk through, like water.

### wall

| Field | Type | Required | Notes |
|---|---|---|---|
| `type` | `"wall"` | yes | |
| `locations` | array of Location | yes | At least two points. Adjacent points are joined into wall segments. |
| `blocksSight` | boolean | no | Default `true`. |

```json
{
  "type": "wall",
  "locations": [
    { "x": 0.0, "y": 0.0 },
    { "x": 10.0, "y": 0.0 },
    { "x": 10.0, "y": 15.0 }
  ]
}
```

### circle

| Field | Type | Required | Notes |
|---|---|---|---|
| `type` | `"circle"` | yes | |
| `location` | Location | yes | Center of the circle. |
| `radius` | float | yes | Radius in feet. Maximum 30.0. |
| `blocksSight` | boolean | no | Default `true`. |

```json
{
  "type": "circle",
  "location": { "x": 25.0, "y": 40.0 },
  "radius": 5.0
}
```

## Place

A named area of a map: "Arren's Camp", a goblin village, the far end of a cave. Places give a map
structure for building a zone in layers (the layout, then places, then who lives there, then
quests), so a person or an LLM can say "goblins in `goblin_village_5`" rather than giving
coordinates. The game never reads them; the map editor shows them, and tools read and write them.

They're optional, and needn't cover the map or keep apart; but those Auto Barriers makes from a
generated cell map (see **CellMap**) partition it, every bit of open ground in exactly one place,
each running out over the fill to the walls that bound it. So places are adjacent where open
ground passes from one to the other. Where places nest (one inside another's outline), a point
is in the smallest place around it.

| Field | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | yes | Lowercase letters, digits, `-` and `_`; unique on the map. |
| `name` | string | no | Display name, at most 80 characters. |
| `description` | string | no | Free text, at most 4000 characters. |
| `tags` | array of string | no | Free-form, at most 24, each at most 16 characters. |
| `polygon` | array of Location | yes | 3 to 1000 points in map feet, the outline (closed back to the first). |
| `annotations` | Annotations | no | Notes for an LLM, kept between the steps of building a zone. See [common.md](common.md#annotations). |

```json
{
  "identifier": "arrens_camp",
  "name": "Arren's Camp",
  "tags": ["camp", "friendly"],
  "polygon": [{ "x": 10, "y": 10 }, { "x": 60, "y": 12 }, { "x": 55, "y": 50 }, { "x": 8, "y": 45 }],
  "annotations": { "population": "Arren and two guards; quiet by day." }
}
```

## Interactable

Something on the map a player uses for a quest's `use` objective (see [quest.md](quest.md#objective)):
a snare to cut, a totem to break, a cage to open. It's an image drawn into the map, not a token (no
ring, no label), so it can blend in; its name shows on hover and while using it, and it's softly
highlighted on hover or in range.

Each player uses it for themselves, and it does nothing outside a quest that lists it. To a player
with an active `use` objective that lists it, and who hasn't used it yet, it's **available**: drawn
from `imageUrl`, and used by right-clicking it within 10 feet of its edge. That takes `useTime`
seconds, with a cast bar, under the rules of a power's cast: moving (more than half a foot)
cancels it, and a landed hit pushes it back. Once they've used it, while that quest is active,
it's drawn as `whenUnavailable` says; to anyone else it's hidden.

| Field | Type | Required | Default | Notes |
|---|---|---|---|---|
| `identifier` | string | yes | | Unique among the zone's interactables. |
| `name` | string | yes | | Shown on hover and in the cast bar. |
| `imageUrl` | string | yes | | A transparent-background image, relative to the file it's written in. |
| `usedImageUrl` | string | no | | Drawn once the player has used it, when `whenUnavailable` is `used` (a cut snare). |
| `whenUnavailable` | string | no | `hidden` | After using it: `hidden` (not drawn) or `used` (drawn from `usedImageUrl`, which it then needs). |
| `size` | object | yes | | `{width, height}` in feet, each 0.5 to 40: the image's size, centered on `position`. |
| `position` | Position | yes | | Its middle, and its turn (`angle`). |
| `useTime` | number | no | `1` | Seconds to use it, 0 to 30; 0 is instant. |
| `useText` | string | no | | The cast bar's label ("Cutting"), at most 40 characters; without it, the name. |
| `annotations` | Annotations | no | | Notes for an LLM. Never read at runtime. See [common.md](common.md#annotations). |

```json
{
  "identifier": "snare-1",
  "name": "Goblin Snare",
  "imageUrl": "../../images/interactable/snare.webp",
  "usedImageUrl": "../../images/interactable/snare-cut.webp",
  "whenUnavailable": "used",
  "size": {"width": 4, "height": 3},
  "position": {"x": 120.0, "y": 340.0, "angle": 0.0},
  "useText": "Cutting"
}
```

## MapConnection

Connections are entry/exit points used to move between maps or enter the zone.

### Common Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `identifier` | string | yes | Slug used to reference this connection within the zone (e.g. `"landing_site"`). |
| `type` | string | yes | `"point"` or `"line"`. |

### point

A positional trigger. Units departing via this connection must intersect `position`. Units arriving via this connection are placed randomly within `fuzzRadius` feet and `fuzzAngle` degrees of `position`.

| Field | Type | Required | Notes |
|---|---|---|---|
| `position` | Position | yes | Location and facing direction of the connection point. |
| `fuzzRadius` | float | yes | Arrival scatter radius in feet. Range: 0.0-20.0. |
| `fuzzAngle` | float | yes | Arrival scatter angle in degrees. Range: 0.0-360.0. |

```json
{
  "identifier": "landing_site",
  "type": "point",
  "position": { "x": 12.0, "y": 8.0, "angle": 270.0 },
  "fuzzRadius": 2.0,
  "fuzzAngle": 90.0
}
```

### line

A threshold. Units crossing the line segment activate the connection.

| Field | Type | Required | Notes |
|---|---|---|---|
| `start` | Location | yes | One end of the threshold line. |
| `end` | Location | yes | Other end of the threshold line. |

```json
{
  "identifier": "north_door",
  "type": "line",
  "start": { "x": 8.0, "y": 20.0 },
  "end": { "x": 12.0, "y": 20.0 }
}
```

## Example

```json
{
  "identifier": "ground_floor",
  "name": "Ground Floor",
  "imageUrl": "../../assets/maps/goblin-cave-ground.png",
  "pixelDimensions": { "width": 2048, "height": 1536 },
  "feetDimensions": { "width": 60.0, "height": 45.0 },
  "barriers": [
    {
      "type": "wall",
      "locations": [
        { "x": 0.0, "y": 0.0 },
        { "x": 60.0, "y": 0.0 },
        { "x": 60.0, "y": 45.0 },
        { "x": 0.0, "y": 45.0 },
        { "x": 0.0, "y": 0.0 }
      ]
    },
    {
      "type": "circle",
      "location": { "x": 30.0, "y": 22.5 },
      "radius": 4.0
    }
  ],
  "connections": [
    {
      "identifier": "landing_site",
      "type": "point",
      "position": { "x": 50.0, "y": 38.0, "angle": 0.0 },
      "fuzzRadius": 1.5,
      "fuzzAngle": 120.0
    },
    {
      "identifier": "entrance",
      "type": "line",
      "start": { "x": 8.0, "y": 0.0 },
      "end": { "x": 12.0, "y": 0.0 }
    }
  ]
}
```
